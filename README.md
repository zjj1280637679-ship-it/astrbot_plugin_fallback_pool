# AstrBot 智能回退模型池

`astrbot_plugin_fallback_pool` 是一个面向 AstrBot 回退模型链的动态调度插件。

它不要求先准确判断“API 坏了、供应商过载、网络卡住，还是上下文吃撑了”。插件把每次调用结果视为一条证据，根据近期失败密度动态降低模型优先级，再通过时间衰减和成功调用逐步恢复信任。在信息不完全的情况下，尽量让下一次轮换顺序更接近当前的最优选择。

## 核心行为

假设原始模型池为：

```text
A → B → C → D → E
```

默认策略下：

- A 偶发失败一次：只轻微降权，通常变成 `B → A → C → D → E`。
- A 在十分钟内累计五次可信失败：直接排到模型池末尾，但仍然可被兜底选中。
- 后续没有新故障：失败证据按指数衰减，A 会逐步回到原始位置。
- A 后续调用成功：立即削弱已有负面证据，加快恢复。
- 明确识别到余额耗尽、消费上限或每日额度耗尽：可将对应模型临时从候选池摘除数小时，避免每条消息都再次撞上确定性失败。

插件不会修改用户配置里的基础顺序。动态排序只存在于运行时，并由持久化的信任账本提供依据。

## 为什么不是简单的线性扣分

插件使用非线性后移曲线：

| 当前有效失败证据 | 默认行为 |
|---|---|
| 很低 | 保持原位 |
| 约 1 次 | 后移 1 位 |
| 约 2 次 | 后移 2 位 |
| 连续形成故障簇 | 快速移向池尾 |
| 十分钟内 5 次 | 直接置底 |

“十分钟内五次失败”和“几小时内零散五次失败”不会被当成同一件事。前者代表当前异常概率迅速上升，后者会因为时间衰减而明显减弱。

## 同时保留两种解释

超时等模糊错误可能来自两种原因：

1. 模型或 API 当前不健康；
2. 当前请求太重，例如超长上下文、多图、大量工具定义或复杂工具历史。

因此，插件默认把模糊失败证据拆成：

- 65%：模型全局状态；
- 35%：当前请求负载桶。

明确的上下文超限只影响对应负载桶；明确的服务器过载主要影响模型全局状态。这样可以降低“某次巨型上下文失败，导致普通短对话也长期绕开该模型”的概率。

当前负载桶分为：

```text
small / medium / large / huge
```

它们根据上下文文本量、图片、音频和工具定义做近似估算，不会读取或上传消息内容。

## 安装

在 AstrBot 插件管理页面中，通过仓库地址安装：

```text
https://github.com/zjj1280637679-ship-it/astrbot_plugin_fallback_pool
```

当前版本要求：

```text
AstrBot >= 4.27 且 < 5.0
Python >= 3.12
```

安装并启用后，插件会包装 AstrBot 的 `ToolLoopAgentRunner`。原始回退循环仍由 AstrBot 自己执行；插件只负责：

1. 在调用前重排候选模型；
2. 保留原主模型的显式 `request.model` 归属，避免重排后把错误模型名传给其他供应商；
3. 观察每个候选的成功、错误响应或异常；
4. 更新并持久化信任账本。

## 管理指令

以下指令仅限 AstrBot 管理员使用。

### 查看状态

```text
/fallback_pool status
```

显示模型的健康状态、全局证据、最高负载桶证据、成功/失败次数，以及临时禁用到期时间。

### 恢复原始信任

恢复全部记录：

```text
/fallback_pool reset all
```

按供应商 ID、模型名或状态键进行模糊匹配：

```text
/fallback_pool reset claude
```

`reset` 会清除降权证据和禁用状态，相当于完全重新信任该模型。

### 手动临时禁用

禁用 60 分钟：

```text
/fallback_pool disable claude 60
```

分钟数小于等于 0 表示无限期禁用：

```text
/fallback_pool disable claude 0
```

### 取消禁用

```text
/fallback_pool enable claude
```

`enable` 只取消禁用，保留已有动态降权证据；需要完全复原时使用 `reset`。

## WebUI 配置

插件自带 `_conf_schema.json`，可在 AstrBot 插件配置页面调整：

- 突发故障观察窗口；
- 多少次失败直接置底；
- 模糊故障分配给全局状态的比例；
- 失败证据半衰期；
- 成功一次后保留多少历史失败证据；
- 普通额度和每日额度的暂停时长；
- 是否记录重排日志与脱敏错误摘要。

默认值就是当前设计目标：单次轻罚、短时密集失败重罚、随时间自动恢复。

## 数据与隐私

状态账本位于：

```text
data/plugin_data/astrbot_plugin_fallback_pool/trust_ledger.json
```

账本保存：

- AstrBot 供应商实例 ID；
- 模型名；
- 时间戳、错误类别和证据强度；
- 脱敏后的短错误摘要；
- 临时禁用状态；
- 成功与失败计数。

插件不会保存 API Key。错误摘要会尝试清除 `Bearer` Token、`sk-...` 和常见 API Key 字段，也可以在配置中完全关闭错误摘要存储。

## 当前边界

v0.1.0 是可运行的第一版，边界如下：

- 只接管 AstrBot 内置 `ToolLoopAgentRunner` 的聊天模型回退链；Dify、Coze、DeerFlow 等独立运行器不在本版范围内。
- 状态粒度是“供应商实例 + 模型”，尚未细分到供应商内部轮换的单个 API Key。
- 插件依赖 AstrBot 4.27 的内部方法形状，加载时会进行兼容性检查；不兼容时不会让 AstrBot 崩溃，管理指令会显示补丁未生效原因。
- 明确的请求参数错误、认证错误和模型不支持能力等，不会被当作普通 API 健康故障全局扣分。
